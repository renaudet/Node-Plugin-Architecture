npa.system.call — OS Process Plugin

Overview

The npa.system.call plugin spawns and tracks OS-level child processes from within NPA plugins. It wraps Node.js's child_process.spawn() and maintains an in-memory table of process wrappers with their status, output and exit code.

Unlike the other NPA plugins, npa.system.call does not register a named service. It is accessed directly through the runtime:
let sysCall = plugin.runtime.getPlugin('npa.system.call');

Methods

executeCommand(launchConfiguration, onLaunched, onCompleted)

Spawns a child process according to launchConfiguration and calls onLaunched(err, pid) immediately after the process starts. onCompleted() is called (with no arguments) when the process exits.

The launchConfiguration object supports the following fields:

FieldTypeDescription
commandstringExecutable to run
workDirstringWorking directory for the process
detachedbooleanRun the process detached from the Node.js event loop
shellbooleanRun inside a system shell (sh / cmd.exe)
inheritbooleanInherit the current process environment variables
environmentobjectAdditional environment variables to set

All stdout and stderr output is captured line-by-line in the process wrapper's output array and retrievable by PID via the process map.

Usage Example

 1. let sysCall = plugin.runtime.getPlugin('npa.system.call');
 2. 
 3. let config = {
 4.   "command": "ls",
 5.   "workDir": "/tmp",
 6.   "shell": true,
 7.   "inherit": true,
 8.   "environment": {}
 9. };
10. 
11. sysCall.executeCommand(
12.   config,
13.   function(err, pid) {
14.     if(err) {
15.       plugin.error('Failed to launch: ' + err);
16.     } else {
17.       plugin.info('Process started, PID: ' + pid);
18.     }
19.   },
20.   function() {
21.     let wrapper = sysCall.process[pid];
22.     plugin.info('Exit code: ' + wrapper.exitCode);
23.     plugin.info('Output: ' + wrapper.output.join('\n'));
24.   }
25. );

Notes

  • Process wrappers are kept in memory for up to 5 minutes after completion, then removed by an internal reaper thread.
  • The reaper thread is only active while at least one process is still running.
  • No argument list is passed to the command — use shell: true to compose complex command lines with pipes or redirections.
