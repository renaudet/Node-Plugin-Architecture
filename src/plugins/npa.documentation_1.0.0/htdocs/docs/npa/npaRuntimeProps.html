npa.runtime.props — Runtime Properties Plugin

Overview

The npa.runtime.props plugin provides a shared, in-memory key/value store for runtime configuration values. Properties are declared by any plugin via the npa.runtime.property.provider extension point and can be read or written at runtime by any other plugin through the properties service:
let propService = plugin.getService('properties');
When a property changes, the plugin emits events through the broker service: runtime.property.created, runtime.property.updated and runtime.property.locked.

Service Name

'properties'

Methods

getProperty(propertyName)

Returns the current value of the named property, or undefined if not found.

setProperty(propertyName, value)

Updates the value of a property. If the property is locked, the call is silently ignored. Returns the effective value after the call.

lockProperty(propertyName)

Permanently locks a property so its value can no longer be changed via setProperty().

getProperties()

Returns all registered properties as an array of property descriptor objects.

Declaring a Property

Properties are declared in a plugin's manifest.json using the npa.runtime.property.provider extension point:
 1. {
 2.   "point": "npa.runtime.property.provider",
 3.   "id": "my.plugin.property.maxRetry",
 4.   "name": "my.plugin.max.retry",
 5.   "description": "Maximum number of retry attempts",
 6.   "type": "int",
 7.   "value": 3,
 8.   "locked": false
 9. }
Supported types: string, int, boolean, moment, percentage.

Usage Example

 1. let propService = plugin.getService('properties');
 2. 
 3. // read a property
 4. let maxRetry = propService.getProperty('my.plugin.max.retry');
 5. 
 6. // update it at runtime
 7. propService.setProperty('my.plugin.max.retry', 5);
 8. 
 9. // lock it so it can no longer be changed
10. propService.lockProperty('my.plugin.max.retry');

Notes

  • Properties are initialised at startup from extension point declarations and reset on every server restart — they are not persisted to disk or database.
  • A property name that is not declared cannot be created at runtime via setProperty(); it must be contributed through the extension point.
  • Change events are only emitted when the broker service is available.
