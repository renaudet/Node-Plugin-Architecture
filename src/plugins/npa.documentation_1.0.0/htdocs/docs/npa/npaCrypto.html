npa.crypto — Cryptography Plugin

Overview

The npa.crypto plugin provides symmetric encryption and decryption services using the AES-256-CBC cipher, plus a random key generator. It is registered as a service under the name cryptography:
let crypto = plugin.getService('cryptography');

Service Name

'cryptography'

Methods

encrypt(data, key?)

Encrypts a UTF-8 string using AES-256-CBC and returns the result as a hex string. key is optional — if omitted, the built-in default key is used. The key must be exactly 32 characters long.

decrypt(encryptedData, key?)

Decrypts a hex string produced by encrypt() and returns the original UTF-8 string. The same key used for encryption must be supplied.

generateRandomKey()

Generates and returns a random 32-character alphanumeric string suitable for use as an AES-256 key.

Usage Examples

Encrypt and decrypt with the default key

1. let crypto = plugin.getService('cryptography');
2. 
3. let encrypted = crypto.encrypt('my secret value');
4. plugin.info('encrypted: ' + encrypted);
5. 
6. let original = crypto.decrypt(encrypted);
7. plugin.info('original: ' + original);

Encrypt and decrypt with a custom key

1. let crypto = plugin.getService('cryptography');
2. 
3. let key = crypto.generateRandomKey();
4. let encrypted = crypto.encrypt('sensitive data', key);
5. let decrypted = crypto.decrypt(encrypted, key);
6. // decrypted === 'sensitive data'

Storing encrypted credentials in a plugin

 1. let crypto = plugin.getService('cryptography');
 2. 
 3. // store encrypted password in config
 4. let encryptedPwd = crypto.encrypt(plainPassword);
 5. 
 6. // later, recover it before use
 7. let plainPassword = crypto.decrypt(encryptedPwd);

Notes

  • The cipher is AES-256-CBC with a fixed initialisation vector. This is suitable for configuration data and tokens, but not as a general-purpose cryptographic library for user-facing data.
  • The default key is built into the plugin. For production use, always supply your own 32-character key and store it outside the codebase (e.g. as an environment variable).
  • Both encrypt() and decrypt() are synchronous and return the result directly — no callback needed.
