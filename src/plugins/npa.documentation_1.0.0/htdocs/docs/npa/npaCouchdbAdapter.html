npa.couchdb.adapter — CouchDB Persistence Plugin

Overview

The npa.couchdb.adapter plugin is the primary persistence layer for NPA and APAF. It wraps Apache CouchDB's HTTP API into a uniform CRUD interface and is accessed through the NPA service registry under the name couchdb:
let couchdb = plugin.getService('couchdb');
Datasources (database connections) are declared via the npa.couchdb.adapter.datasource extension point in each plugin's manifest.json, and resolved at startup by a string reference key passed to every API call.

An optional environment variable COUCH_DATABASE_PREFIX can be set to prefix all database names — useful to separate dev/staging/production data in a shared CouchDB instance.

Service Name

'couchdb'

Methods

query(reference, query, callback)

Executes a CouchDB Mango query and returns an array of matching documents.
query is a standard CouchDB Mango query object ({ selector: {...} }). The limit defaults to the datasource's maxPageSize if not specified.

findByPrimaryKey(reference, data, callback)

Retrieves a single document by its id field. Returns null (not an error) if the document does not exist.

createRecord(reference, data, callback)

Creates a new document. If data.id is absent a UUID v4 is generated automatically. On success, the callback receives the record with its newly assigned _rev field.

updateRecord(reference, data, callback)

Updates an existing document. The method first reads the latest revision from CouchDB, then merges the incoming fields on top of it (fields absent from data are preserved), and writes the merged result back. The callback receives the fully merged, updated record.

deleteRecord(reference, data, callback)

Deletes a document identified by data.id. The method resolves the current _rev automatically before issuing the DELETE.

checkDatabase(reference, callback)

Checks whether the target database exists. Callback: function(err, exists).

createDatabase(reference, callback)

Creates the target CouchDB database if it does not already exist.

deleteDatabase(reference, callback)

Permanently deletes the target CouchDB database and all its documents.

Usage Examples

Querying documents with a Mango selector

 1. let couchdb = plugin.getService('couchdb');
 2. let query = { "selector": { "type": { "$eq": "snippet" } } };
 3. 
 4. couchdb.query('my.datasource', query, function(err, docs) {
 5.   if(err) {
 6.     plugin.error('Query failed: ' + err);
 7.   } else {
 8.     // docs is an array of CouchDB documents
 9.     for(var i = 0; i < docs.length; i++) {
10.       plugin.info('found: ' + docs[i].name);
11.     }
12.   }
13. });

Creating a record

 1. let couchdb = plugin.getService('couchdb');
 2. let record = {
 3.   "name": "myRecord",
 4.   "value": 42
 5. };
 6. 
 7. couchdb.createRecord('my.datasource', record, function(err, created) {
 8.   if(err) {
 9.     plugin.error('Create failed: ' + err);
10.   } else {
11.     plugin.info('Created with id: ' + created.id);
12.   }
13. });

Updating a record

 1. let couchdb = plugin.getService('couchdb');
 2. // only provide the fields to change; other fields are preserved
 3. let patch = { "id": "abc-123", "value": 99 };
 4. 
 5. couchdb.updateRecord('my.datasource', patch, function(err, updated) {
 6.   if(err) {
 7.     plugin.error('Update failed: ' + err);
 8.   } else {
 9.     plugin.info('Updated _rev: ' + updated._rev);
10.   }
11. });

Declaring a Datasource

Datasources are declared in the contributing plugin's manifest.json:
 1. {
 2.   "point": "npa.couchdb.adapter.datasource",
 3.   "id": "my.plugin.datasource",
 4.   "reference": "my.datasource",
 5.   "hostname": "127.0.0.1",
 6.   "port": "5984",
 7.   "dbname": "my_database",
 8.   "maxPageSize": 500,
 9.   "environment": {
10.     "hostname": "MY_COUCH_HOST",
11.     "port": "MY_COUCH_PORT",
12.     "username": "MY_COUCH_USER",
13.     "password": "MY_COUCH_PASSWD"
14.   }
15. }
When an environment block is present, the corresponding environment variables override the static values at startup.

Notes

  • All callbacks follow the Node.js error-first convention: function(err, result).
  • updateRecord performs a read-then-write and merges fields, so concurrent updates to the same document from multiple callers may overwrite each other — use with care in high-concurrency scenarios.
  • Database transactions are counted and pushed to the database.transaction telemetry dimension every 30 seconds.
