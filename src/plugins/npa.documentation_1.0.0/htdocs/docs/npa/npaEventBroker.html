npa.event.broker — Event-Driven Plugin

Overview

The npa.event.broker plugin implements a server-side publish/subscribe bus on top of Node.js's built-in EventEmitter. It enables decoupled communication between plugins without direct imports. The service is available as broker:
let broker = plugin.getService('broker');

Service Name

'broker'

Event Structure

Every event passed to emit() must carry at least a name and a data field. A source field is optional but recommended for debugging:
{
  "name": "my.event.name",  // required
  "source": "my.plugin",   // optional
  "data": { ... }       // required
}
The broker automatically stamps each event with an emitted timestamp before dispatching it to registered handlers.

Methods

emit(event)

Publishes an event to all registered handlers for event.name. Returns true on success, false if the event is malformed.

registerHandler(eventName, handlerId, handlerCallback)

Subscribes handlerCallback to events named eventName. handlerId is a unique identifier for this subscription (used to unregister it later). The callback receives the full event object: function(event). Handler errors are caught and logged — a failing handler never crashes the bus.

unregisterHandler(eventName, handlerId)

Removes the subscription registered under handlerId for eventName.

unregisterAllHandler(eventName)

Removes all subscriptions for eventName, regardless of their handler ID.

Usage Examples

Publishing an event

1. let broker = plugin.getService('broker');
2. 
3. broker.emit({
4.   "name": "user.loggedIn",
5.   "source": "apaf.security",
6.   "data": { "login": "john.doe" }
7. });

Subscribing to an event

 1. let broker = plugin.getService('broker');
 2. 
 3. broker.registerHandler(
 4.   'user.loggedIn',
 5.   'my.plugin.loginWatcher',
 6.   function(event) {
 7.     plugin.info('User logged in: ' + event.data.login);
 8.   }
 9. );

Unsubscribing

1. broker.unregisterHandler('user.loggedIn', 'my.plugin.loginWatcher');

Notes

  • The underlying EventEmitter has no listener limit (setMaxListeners(0)), so any number of handlers can be registered for a given event name.
  • Events are dispatched synchronously in the order handlers were registered.
  • Several core plugins emit well-known events: workspace.file.created, workspace.file.updated, workspace.project.created, runtime.property.created, runtime.property.updated, runtime.property.locked.
