npa.jobs — Job Management Plugin

Overview

The npa.jobs plugin provides an in-memory job tracking service for long-running server-side operations. A job is a lightweight record that carries status and progress information so that a browser client can poll for completion without blocking. The service is available as jobs:
let jobService = plugin.getService('jobs');

Service Name

'jobs'

Job Lifecycle

A job moves through the following statuses:

pending → ongoing → completed
                     → setRollbackOnly → terminated

Jobs that are not revalidated within the expiration timeout (default 60 s) are automatically marked setRollbackOnly and then terminated. Completed jobs are purged after the same expiration delay.

Methods

createJob(owner, description, longRunning?)

Creates a new job record with status pending and returns it. owner is a string identifier (e.g. a username). Set longRunning to true to prevent expiration-based cleanup until the job completes.

getJob(jobId)

Retrieves a job by its ID. The first call transitions the status from pending to ongoing and stamps the revalidation time — repeated polling keeps the job alive.

updateJob(job)

Updates progress and/or status of an ongoing job. Set job.progress (0–100) to report advancement. Set job.status to 'completed' or 'setRollbackOnly' to terminate the job. Returns the updated internal job record.

getJobs()

Returns the full list of currently tracked jobs as an array.

Usage Example

Server side: creating and progressing a job

 1. let jobService = plugin.getService('jobs');
 2. 
 3. // create the job and return its ID to the caller
 4. let job = jobService.createJob('admin', 'Importing data...');
 5. 
 6. // simulate progress in an async operation
 7. setTimeout(function() {
 8.   jobService.updateJob({ "id": job.id, "progress": 50 });
 9. }, 2000);
10. 
11. setTimeout(function() {
12.   jobService.updateJob({ "id": job.id, "progress": 100, "status": 'completed' });
13. }, 5000);
14. 
15. // return the job ID to the browser so it can poll
16. then(null, { "jobId": job.id });

Browser side: polling for completion

 1. pollJob = function(jobId) {
 2.   apaf.call({ "method": "GET", "uri": "/apaf-jobs/job/" + jobId, "payload": {} })
 3.     .then(function(job) {
 4.       if(job.status === 'completed') {
 5.         showSuccess('Done!');
 6.       } else if(job.status === 'terminated') {
 7.         showError('Job failed');
 8.       } else {
 9.         setTimeout(function() { pollJob(jobId); }, 1000);
10.       }
11.     })
12.     .onError(function(msg) { showError(msg); });
13. }

Notes

  • Jobs are stored in memory only — they are lost on server restart.
  • The check loop runs every 30 seconds by default (configurable via the job.check.loop.timeout runtime property).
  • The expiration delay is 60 seconds by default (configurable via job.expiration.timeout).
  • Long-running jobs (flag longRunning: true) are exempt from expiration until they reach completed status.
