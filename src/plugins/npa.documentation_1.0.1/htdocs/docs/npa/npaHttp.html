npa.http — HTTP Endpoint Provider Plugin

Overview

The npa.http plugin hosts the Express HTTP(S) listener of the NPA server. Other plugins contribute routers, REST handlers, WebSocket handlers, static content and the home page through its extension points. The plugin also manages the HTTP session store (in-memory or persisted in CouchDB) and exposes session counters as runtime properties and as a telemetry dimension. It is registered as the core service http.

Version 1.1.0 — Configurable request body size limits

Up to version 1.0.0, the maximum size of request bodies (POST, PUT, ...) was hard-coded in the plugin. Starting with 1.1.0, each limit is read from the http.bodyLimit section of the plugin configuration (manifest.json) and can be overridden with an environment variable. A request whose body exceeds the limit is rejected by the server with an HTTP 413 (Payload Too Large) error before reaching any handler.
Content-Type Configuration key Environment variable Default
application/json http.bodyLimit.json HTTP_BODY_LIMIT_JSON 1mb (500kb in 1.0.0)
application/x-www-form-urlencoded http.bodyLimit.urlencoded HTTP_BODY_LIMIT_URLENCODED 500kb
application/octet-stream http.bodyLimit.raw HTTP_BODY_LIMIT_RAW 50mb
text/* http.bodyLimit.text HTTP_BODY_LIMIT_TEXT 100kb
The limits apply to every HTTP verb carrying a body and to all routers of the server. Values use the body-parser syntax: a number of bytes, or a string such as 500kb, 1mb, 50mb.

Configuration

The default values are declared in the http section of the plugin manifest, using the $ENV_VARIABLE,defaultValue syntax resolved by getConfigValue():
 1. "http": {
 2.   ...
 3.   "bodyLimit": {
 4.     "json": "$HTTP_BODY_LIMIT_JSON,1mb",
 5.     "urlencoded": "$HTTP_BODY_LIMIT_URLENCODED,500kb",
 6.     "raw": "$HTTP_BODY_LIMIT_RAW,50mb",
 7.     "text": "$HTTP_BODY_LIMIT_TEXT,100kb"
 8.   }
 9. }
To accept larger JSON payloads without changing any file, set the environment variable before starting the server, for example HTTP_BODY_LIMIT_JSON=5mb.

Runtime Properties and Telemetry

  • http.service.port — TCP port of the listener (locked once the listener is started).
  • http.service.ssl.enabled — whether HTTPS is enabled (locked once the listener is started).
  • http.session.count — current number of sessions in the store.
  • http.session.authenticated.count — current number of active (authenticated) sessions.
  • Telemetry dimension http.session — number of active sessions, sampled every 30 seconds.

Notes

  • Body limits are read once, when the plugin starts: a server restart is required after changing a value.
  • The npa.http manifest does not contribute to the documentation collector, because npa.documentation depends on npa.http. This page is therefore hosted and declared by npa.documentation (since version 1.0.1).
  • A 413 error received by a client usually means that the body of the request is larger than the limit configured for its Content-Type: raise the matching limit rather than modifying the code.
