npa.compiler — Generic Compiler Plugin

Overview

The npa.compiler plugin provides a fully data-driven, rule-based compiler and execution engine for NPA. It exposes a compiler service that any plugin can consume to parse and execute custom languages without writing tokenizer or parser code from scratch.

The pipeline consists of three stages:
  • Tokenizer — splits the source into a flat token list according to the tokenization rules of the grammar configuration
  • Syntax analyser — validates the token list against the compilation rules and produces an ExecutionUnit tree
  • Execution engine — walks the ExecutionUnit tree and delegates each node to the language runtime plugin
The grammar itself (tokenization rules, compilation rules, root rule) is a plain JSON configuration object that is passed at runtime. Swapping that configuration object changes the language without modifying any JavaScript.

Service registration

npa.compiler registers itself as the compiler NPA service via the npa.core.service extension point. Consumer plugins obtain a reference with:
 1. // inside plugin.js
 2. let compilerService = this.getService('compiler');
The manifest dependency is:
 1. { "type": "plugin", "id": "npa.compiler", "version": "1.0.0" }

API Reference

compile(source, grammarConfig)

Tokenizes and parses source according to the grammar described in grammarConfig. Returns an object with two fields:
FieldTypeDescription
euExecutionUnit | nullRoot of the compiled execution tree. null if compilation failed.
errorstring | nullError message if compilation failed, null on success.
 1. let result = compilerService.compile(source, grammarConfig);
 2. if (!result.eu) {
 3.   console.error(result.error);
 4. }

execute(eu, builtins, enginePlugin, context)

Executes a previously compiled ExecutionUnit tree. Returns an object with three fields:
FieldTypeDescription
successbooleantrue if execution completed without raising a halt flag.
errorstring | nullHalt message if execution failed, null on success.
memorySpaceobjectSnapshot of all top-level variables after execution.
Parameters:
ParameterTypeDescription
euExecutionUnitRoot execution unit returned by compile().
builtinsobjectMap of native JS functions to expose to the script. Each value is either a plain function (sync) or { fn, async: true } (async).
enginePluginobjectLanguage runtime plugin that handles each ExecutionUnit node type. Must implement process(eu, engine), callFunction(name, args, engine) and halt(msg, engine).
contextobjectOptional. Map of variable name → initial value pre-loaded into the engine memory space before execution starts.

 3.   { print: (txt) => console.log(txt) },
 4.   myLanguagePlugin,
 5.   { request: req, response: {} }

run(source, grammarConfig, builtins, enginePlugin, context)

Convenience method that calls compile() then execute() in a single step. Returns the same object as execute(). If compilation fails, returns { success: false, error: <message>, memorySpace: {} }.

 3.   grammarConfig,
 4.   builtins,
 5.   myLanguagePlugin

Logging

All compiler and engine trace, debug, info, warning and error output is routed through the NPA logging service. The plugin registers its log directory under npa.compiler. Set the log level for this directory to trace or debug in the site configuration to obtain detailed compilation and execution traces.
